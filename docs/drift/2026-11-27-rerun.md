# Drift rerun for 0.2.0 (2026-11-27)

A rerun of the [2026-11-26 baseline](2026-11-26-baseline.md) after the hardening changes.

## How this was run

Run on 2026-11-27 with Claude Code 2.1.332, on `main` at `464aa4b` (plugin version `0.2.0-dev.6`), against the same frozen fixture and with the same five commands as the baseline, using `--out drift-runs/0.2.0-dev.6`. One extra context run (`--runs 1 --tag smoke-context`) came first to check the models. It is not part of any set below.

The five sets are 61 calls. All five commands exited 0 and no result file reports an error.

**What changed since the baseline** (`ba2994a`):

- The scorer agent and the skills were hardened (#44, #46, #48). These edits can change scores.
- `run.sh` now runs the `claude` session on sonnet in every call (#62). In the baseline, the session ran on Opus in the sets labelled `sonnet`.
- `run.sh` gained a per-call timeout, and context mode now allows `Edit` inside the sandbox instead of `Write` (#52).
- The analyzer reports ties and per-run costs (#50).

This rerun cannot separate the effects of these changes.

**Models used.** The result files list only `claude-sonnet-5-5` for both sonnet scorer sets, both context sets and the smoke run. Each call in the opus set lists `claude-sonnet-5-5` (the session) and `claude-opus-5-5`.

**Cost.** Independent sonnet 4.61 USD, independent opus 6.34, centralized sonnet 2.19, `with-docs` 0.48, `no-docs` 0.45: 14.06 USD for the five sets. With the smoke run (0.26), 14.32 USD. The baseline cost 17.04 USD with Opus sessions, so the two are not directly comparable. The highest single scorer call was 0.44 USD.

**Unreadable replies and the analyzer fix.** As first run, the analyzer could not read 4 of the 55 scorer replies, because their `json` fences were indented by two spaces (#63, fixed in #64). The figures below use the fixed analyzer on the same saved outputs; no calls were repeated. Whether the scorer subagent or the relaying session adds the indent was not checked. Separately, 2 replies end with the Agent tool's `agentId` and usage text (#66). With the fixed analyzer, the comparison rows for the saved baseline outputs match the baseline report.

**Denied commands.** All 6 context runs and the smoke run had denied Bash commands, 12 in total, all creating the run directory and ending in `cd ... && pwd`. Every run still wrote `locked-context.md`. The baseline reported no permission denials. The suspected cause is not confirmed (#65). The scorer sets had no denials.

The raw outputs are in `drift-runs/0.2.0-dev.6/`, which is not committed.

## Reading

Each scorer set has only 5 runs and each context arm only 3, so this reports what varied and makes no claim of statistical significance.

**First place often depends on the tie rule.** `score.py` orders tied totals by name. Among passing options, totals were tied somewhere in the ranking in 7 of 15 runs (2/5, 2/5 and 3/5), against 2 of 15 in the baseline (1/5, 0/5 and 1/5).

| Set | Resend strictly first | Postmark strictly first | Amazon SES strictly first | Tie for first |
|---|---|---|---|---|
| independent sonnet | 5 | 0 | 0 | 0 |
| independent opus | 2 | 1 | 0 | 2 (Postmark and Resend) |
| centralized sonnet | 2 | 0 | 0 | 3 (Amazon SES and Resend) |

The most common centralized ranking puts Amazon SES first, but SES was never strictly ahead: it is listed first only because it tied with Resend and sorts before it by name. In the same way, opus lists Postmark first in 3 runs, 2 of them by tie. "Same ranking" and pairwise agreement include this rule's effect; the size of that effect on those two figures was not measured. In the baseline, one run (independent sonnet) had a tie for first.

**Compared with the baseline.** Independent sonnet moved from a split between Postmark and Resend to Resend strictly first in all 5 runs. Centralized sonnet moved from Resend first in all 5 runs to the results above, and its pairwise agreement fell from 96% to 90%. It still had the smallest mean total spread (2.4, against 2.6 for opus and 3.8 for independent sonnet) and the fewest varying factor cells (8, 9 and 12). Varying factor cells across the three sets fell from 39 to 29. Independent sonnet's mean total spread rose from 3.0 to 3.8, led by Build (8 points). The close-call flag was set in 15 of 15 runs and no gate outcome varied.

**For #40.** `integration` varied in 8 candidate cells and `lock_in` in 6, followed by `fit` and `dependencies` with 4 each. In the baseline, `lock_in` (10) and `integration` (9) also led, followed by `install` (5). Most varying factors moved by 1 point. The 2-point moves were Build `fit` (both sonnet sets), Build `install` (independent sonnet and opus) and Amazon SES `integration` (independent sonnet).

**Totals differ between sets.** Postal scored 39 to 40 with opus, 45 to 48 with independent sonnet and 46 to 48 centralized, so a small spread within a set does not mean the sets agree.

**Context.** In each arm, one of the 3 runs added `usesend` and `usesend cloud` to the candidate list; the baseline had one candidate set across all 6 runs. The analyzer's count of 3 distinct sets per arm overstates the difference, because it treats differently worded Build descriptions as different candidates when they follow `Build:`. Otherwise the only compared field that differed was the wording of `expected_growth`, which also differed within each arm. Why the two runs added candidates was not investigated. The analyzer does not compare the stack summary or candidate descriptions, and matching fields do not show that documents make no difference, because the shared prompt supplies every interview answer.
