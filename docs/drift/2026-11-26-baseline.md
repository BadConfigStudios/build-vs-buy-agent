# Drift baseline for 0.2.0 (2026-11-26)

## How this was run

Run on 2026-11-26 with Claude Code 2.1.332, on `main` at `ba2994a`, against the frozen fixture in `tools/drift/fixtures/` (locked context dated 2026-11-26, matrix version 1.3, mode `full`, environment `production`, five frozen reports). The commands ran one after another, each with the default cap of 1.50 USD per call:

```bash
bash tools/drift/run.sh --out drift-runs --runs 5 --model sonnet
bash tools/drift/run.sh --out drift-runs --runs 5 --model opus
bash tools/drift/run.sh --out drift-runs --runs 5 --model sonnet --topology centralized
bash tools/drift/run.sh --out drift-runs --mode context --arm with-docs --runs 3
bash tools/drift/run.sh --out drift-runs --mode context --arm no-docs --runs 3
```

That is 61 calls: 25 independent sonnet, 25 independent opus, 5 centralized sonnet (shuffled candidate order) and 3 context runs per arm. All five commands exited 0. The result files report no errors and no permission denials. The highest cost of a single call was 0.59 USD. `run.sh` unsets the model override variables, and it does not pass `--dangerously-skip-permissions`.

**Models used.** The result files list `claude-opus-5-5` for the opus set and `claude-sonnet-5-5` for the context runs. Every call in both sets labelled `sonnet` lists **both** `claude-sonnet-5-5` and `claude-opus-5-5`. The likely reason is that `--model` applies only to the scorer subagent, while the session that runs the `scorer` skill and relays the reply uses the CLI default model. This is inferred from the per-model usage and was not confirmed from a transcript. The costs of the `sonnet` sets include that Opus usage.

**Cost.** The three scorer sets cost 5.33, 8.07 and 2.90 USD. The context runs, which the context report does not price, cost 0.39 USD (`with-docs`) and 0.35 USD (`no-docs`), taken from `total_cost_usd`. The total is 17.04 USD. It excludes the earlier smoke run and an aborted first attempt (9 completed calls, results discarded).

The raw outputs are in `drift-runs/`, which is not committed.

## Reading

Each scorer set has only 5 runs and each context arm only 3, so this reports what varied and makes no claim of statistical significance. Centralized sonnet had the smallest mean total spread (2.4 points, against 2.8 for independent opus and 3.0 for independent sonnet) and the fewest varying factor cells (12, 13 and 14); it tied with independent opus on pairwise order agreement (96%, against 94%). The first place changed between Postmark and Resend in both independent sets (opus: Postmark in 3 runs, Resend in 2; sonnet: Postmark ahead in 2, Resend in 2, tied at 68 in 1), while centralized sonnet put Resend first in all 5 runs and changed only the order of Amazon SES and Postmark below it. Build and Postal also swapped once, in independent sonnet run 4, but the close-call flag did not flip (set in 15 of 15 runs) and no gate outcome varied. The most common ranking in centralized sonnet differs from the one in both independent sets at the top (Resend rather than Postmark), and totals also shift between sets (Postal scored 39 to 40 with opus, 44 to 49 with independent sonnet and 46 to 49 centralized), so a smaller spread within a set does not mean the sets agree with each other. Across the three sets, `lock_in` varied in 10 candidate cells and `integration` in 9, ahead of `install` with 5, so #40 should look at `lock_in` and `integration` first; every varying factor moved by 1 point except `install` for Build with opus (1 to 3). The run sets cost 5.33 USD (independent sonnet), 8.07 USD (independent opus), 2.90 USD (centralized sonnet), 0.39 USD (`with-docs`) and 0.35 USD (`no-docs`). Both context arms gave the same candidate names, and the only compared field that differed was the wording of `expected_growth`, which also differed between runs within each arm. The analyzer does not compare the stack summary or the candidate descriptions, and the files did differ there (the Build description varied between runs, for example on whether it sends through an SMTP relay, and one `with-docs` run formatted its stack summary differently); matching fields also do not show that documents make no difference, because the shared prompt supplies every interview answer and a fallback stack text with nearly the same facts as the fixture README.
